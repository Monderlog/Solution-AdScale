# ADR-001. Стратегия эволюции: Strangler Fig

Статус: принято. Пересмотр через 6 месяцев.

## Контекст

Монолит AdScale работает на пределе, P95 110-120 мс при SLA 100 мс. Через 3 месяца нужно подключить DSP с +20% трафика и SLA 80 мс, через год ожидается рост до 50 000 RPS. Бюджет ограничен, продукт не должен останавливаться, полной документации архитектуры нет.

Варианты: оставить монолит и масштабировать железом, переписать на микросервисы с нуля, постепенная декомпозиция (Strangler Fig), модульный монолит.

## Решение

Strangler Fig. Перед монолитом ставим API Gateway и вырезаем из монолита сервисы по одному, начиная с Bidding Service. Маршрутизация переключается на уровне роута, любой шаг обратим.

## Почему не иначе

- Монолит: hot path нельзя масштабировать отдельно от аналитики, общая БД остаётся узким местом, +20% трафика он уже не выдержит
- Полный переезд с нуля: три месяца и ограниченный бюджет несовместимы с переписыванием семи компонентов, а бизнес требует непрерывности
- Модульный монолит полезен как промежуточный шаг, но независимого масштабирования Bidding до конца срока не даёт

## Последствия

Через 3 месяца получаем изолированный Bidding под новой DSP, остальное доезжает к концу года. Цена вопроса: временно живут две архитектуры, нужен Gateway и аккуратное переключение трафика, часть функциональности в переходный период продублируется.
